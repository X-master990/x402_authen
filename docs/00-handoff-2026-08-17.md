## 三、已定案的策略：一個引擎、兩個榜單、五條收入線

### 產品核心
一套探測引擎：**排程器 → 付費抓取（真的用 x402 付錢買數據）→ 蓋時間戳存檔 → 跟權威來源對答案 → 算分**。
指標：活著嗎、延遲多少、報價 vs 交易所官方差多少、時間戳漂移多少。

用同一套引擎產出兩個公開榜單：
- **榜單 A「x402 金融數據準確度榜」**：生態內、客觀、建立專業信譽。ground truth 用幣安等交易所官方 API + CoinGecko（CoinGecko 官方已把 API 掛上 x402，每次 $0.01，既是對照組也是品類內的品牌賣家）。
- **榜單 B「訊號商成績單」**：收集付費交易訊號（x402 上的與 Telegram 的），逐筆蓋時間戳封存，事後結算真實勝率並公開。流量款、餵內容。

### 驗貨方法論（四招，未來擴品類時複用）
對答案（跟權威來源比）、放金絲雀（自己埋陷阱測爬蟲）、蓋時間戳（事後算總帳）、跑跑分（規格比對）。品類只是設定檔，引擎不變。

## 五、關鍵盡職調查：ScoutScore 的「回應保真度」驗什麼？

**問題**：動工前唯一要確認的事——ScoutScore 的 fidelity 支柱是驗「格式」還是驗「數字準不準」？

**結論：驗的是「有沒有出貨」（付款流程通、有回應、非空包、schema 合格），不是「貨是不是真的」（數據 vs 市場真值）。→ 內容真偽層無人佔據，路是通的。**

證據：
1. 他們付費探測**總花費 $0.78 USDC**（索引 2,060 服務、付費探測 198 網域、85% 收款、收款者中 36% WORK / 64% BROKEN）。$0.78 只買得到「有回應」，買不到持續對答案。
2. 評分呈現為 WORK/BROKEN 式的交付驗證；案例中 fidelity 30 分的說明是「回應品質問題」。
3. 官網六個偵測向量（錢包聚類、複製品偵測、schema 驗證、上架異常、描述/定價一致性、uptime/延遲）無一是 ground truth 比對；PRICE_MISMATCH 指「標價 vs 實收」，非「報價 vs 市場」。

**警訊**：ScoutScore 在 README 親口寫「（保真度）是最難量測的維度，也是護城河最深的地方」——他們看得見這個方向，只是還沒燒錢。**窗口真實存在，但有倒數；假想敵就是他們。** 另外他們已是 ERC-8183 註冊評估者（分數決定託管款放行、評分雜湊上鏈），架構值得研究與借鑑。

差異化定位：Brian = 單一品類鑽深（金融數據準確度、帶時間戳誤差歷史）；ScoutScore = 全生態淺層交付檢查。長期可能是數據供應/合作關係而非零和。附註：Brian 計畫每月 $50–150 探測費，將直接成為全生態在「付費驗貨」上花最多錢的人（現任紀錄保持者總花費 $0.78）——這是護城河的實際標價。
